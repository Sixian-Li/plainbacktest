# Quant 整体平台 GitHub-ready 差距与渐进重构计划

> 源工作区的长期工程讨论。本发行版采用代码、项目 Skill、数据和 README 的朴素发布范围；本文各项不是本版的前置验收要求。

> 调研日期：2026-09-26。代码基线：`3af75e4c3ebf295d8b1f61412060a0384b1d4ce5`。本文是重构路线图，不代表下述方案已经实施，也不代表已完成公开发布审查。

## 1. 目标与结论

目标是把 **整个 Quant 研究平台** 整理成别人能够安装、理解、运行、验证和扩展的 GitHub 项目，覆盖数据接入、指标观察、策略回测、独立账本、参数研究、报告、实验生命周期与研究谱系。最终形态仍是一个完整平台。

最难的工作是把已经服务于个人研究的规则，变成对外稳定的接口，同时证明重构没有改变历史计算含义。现有代码已经有相当多可保留的工程资产；主要成本集中在以下边界：

1. **发布权利**：自有代码许可、引擎许可、数据及派生产物的再分发权必须分别处理。
2. **数据与执行契约**：用户换数据、换标的、换策略后，成交时序、复权、账本与指标含义仍须明确。
3. **平台与个人工作区**：当前固定目录、购买包、DER/ROT/TIM 分类、Agent 流程和正式验证相互依赖。
4. **迁移证据**：拆模块后既要保持旧结果可解释，也要防止两套账本因共享实现而失去交叉检查价值。
5. **外部可用性**：现有测试、环境、报告与文档需要在没有本机数据和个人 Skill 的环境里成立。

建议保留一个仓库和一个主要 Python 包，先建立边界与兼容层，再逐类迁移。现在没有证据表明需要微服务、分布式数据库或重新写一套回测引擎。

本文中的“整个平台”不要求公开购买数据、私人研究记录或每个历史 HTML。平台能力的迁移与研究材料的公开是两条清单；三个代表案例只是迁移起点，不能据此宣称所有现有策略已经迁移。

### 已有能力应保留

- 购买原始数据与派生数据分层，批准、影子、待审候选分离。
- Experiment / Run / Case 分离，冻结配置、来源哈希、生命周期与不可覆盖结果。
- PyBroker 与参考账本的比较，以及成交时序、费用、共享现金等黄金测试。
- 参数稳健性、样本外阶段和不晋级结论；研究结果包含负结果与失败证据。

这些构成平台的主要价值。重构时应保护其含义，而不是只追求更少的文件或更短的命令。

## 4. 逐项分析

### GH-01：先厘清许可证，避免公开定位与依赖冲突

**证据。** [直接依赖](../requirements.in) 锁定 `lib-pybroker==1.2.12`。本次读取安装发行物的 METADATA 和 LICENSE，均确认其许可为 `Apache License 2.0 with Commons Clause`；许可证文件 SHA256 为 `da959ac23cb6eb2636b9389acc0cfec35e7ffa79a0420bb5469a132a2db18650`。[早期框架调研](framework_research.md) 也曾记录这一点。

**为什么难。** 该版本带有对条款所定义收费销售活动的额外限制，不能按普通 Apache-2.0 介绍。上游当前 [LICENSE](https://github.com/edtechre/pybroker/blob/master/LICENSE) 也展示该限制；[OSI 定义](https://opensource.org/osd) 要求自由再分发，并禁止限制商业等用途领域，因此不能把这一附加条件描述成标准 OSI 开源许可。这里没有据此断言“Quant 不能公开”或“任何商业用途都禁止”；自有代码如何许可、依赖如何分发和具体服务如何使用，须分别判断。

**建议。** 建立锁定版本的依赖及许可证清单，覆盖 Python 直接/传递依赖和 HTML 内嵌的第三方 JS。明确自有代码来源与贡献归属，再决定项目 LICENSE、必要归属说明和 README 中的依赖限制。PyBroker 先隔离成 adapter，保留两条可评估路线：继续提供它并明确限制；或在未来有需要时增加许可满足目标的执行实现。把依赖变成 optional 并不会自动消除使用该依赖时的条款。

**验收。** 自有代码许可、第三方声明、数据许可三者可独立查阅；每个发行依赖有精确版本和许可来源；README 不再把整套运行栈承诺为无限制商用。是否更换默认引擎须单独决策，本次不决定。

### GH-02：数据适配器必须携带语义，不能只接受七列 CSV

**证据。** [数据说明](../../data/README.md)、[来源登记](../../data/source_registry.yaml) 和 [能力登记](../../data/data_update_registry.json) 同时管理购买 ZIP/CSV、复权、证券身份、日历、批准价格、候选成员和影子更新。两套成员候选还有来源、授权、取得日期等未签核字段。Git 当前跟踪 `data/processed` 下 **9 个 CSV**，其中 8 个属于两套待审成员产品，另 1 个是当前成分快照；[忽略规则](../../.gitignore) 对待审目录有显式例外。

**为什么难。** 列名相同不等于可用于同一研究：调整后 OHLC 与原始价格不同，成交量可能也被调整；今天的成分不能替代历史时点成员，证券代码也不等于永久身份。现有价格近似总回报，不具备完整独立现金分红/拆股事件账本。数据被购买、被 Git 忽略、通过质量测试，都不能单独证明可再分发。

**建议。** 分开四层：文件解析 → 标准数据与元信息 → 质量验证 → 用途/授权规则。首先支持合成数据和用户自行提供的 canonical CSV；本机购买包与现有 registry 作为私有数据适配器保留。标准契约至少包括：

- 稳定 `security_id`、显示 ticker、时区、交易日历、频率及日期边界。
- 原始/复权价格类型、调整口径、volume 含义、数据内容哈希与来源标识。
- 有效时间与获知时间；成员延迟规则、退市、重入、缺价与左截断政策。
- `registered_status`、`effective_status`、允许研究阶段及独立的再分发授权字段。

未知授权保持未知，公开 fixture 使用自己构造的数据。真实演示数据若要纳入，逐项确认来源及派生材料的公开范围。更新器的 provider、限额、凭据读取和审批策略放在适配层；不把 macOS Keychain 作为所有用户的必需环境。

**验收。** 无购买包、无密钥可运行公共样例；同一策略可换两个 schema 合法的数据集；错误 OHLC、重复日期、缺失成员证据、未批准用途会产生可解释的拒绝。成员时点延迟与身份更换有专门案例。`approved` 不隐含可再分发，`candidate` 不自动晋级。支持范围明确说明公司行动与流动性模型的限制。

### GH-03：公共模块已经存在，但依赖方向仍需改变

**证据。** [execution.py](../quantkit/execution.py) 把成交规格与 PyBroker 类型放在一起；[stochrsi.py](../quantkit/stochrsi.py) 同时包含指标计算与引擎 adapter；[reference.py](../quantkit/reference.py) 又导入 execution、SMA 与 StochRSI 模块。[指标实验台 core](../../research/indicator_lab/core.py) 通过 `sys.path` 导入 `quantkit.stochrsi.wilder_rsi`，因此纯指标需求也传递依赖 PyBroker。[双均线 core](../dual_sma_lab/core.py) 同时依赖策略状态、成交、指标和参考账本。

**为什么难。** 直接把 `quantkit` 复制到新仓库，名字看起来通用，导入时仍会牵入完整引擎和本机目录。反过来先设计一个巨型 Strategy 基类，也容易把单标的、盘中阈值和多资产轮动强塞进错误抽象。

**建议。** 优先提取纯类型、指标计算、成本/时序规格和结果契约，再隔离引擎适配。已有 dataclass、OrderPlan 和测试作为起点，不批量重命名所有模块。旧导入路径通过薄兼容层继续工作，每迁移一种语义就移除其对旧层的依赖。报告与应用从公共服务层取数据，核心不反向导入 Streamlit、CLI 或个人工作流。

**验收。** 未安装 PyBroker/Streamlit 时可以导入纯指标与数据模型；包可在仓库外被导入；新增一个简单策略无需修改核心目录审计或报告模板。逐项保存旧/新路径映射和废弃计划。

### GH-04：统一数据契约比统一命令名更先决

**证据。** [experiment.py 的 validate_experiment_config](../quantkit/experiment.py) 使用手写校验，并包含 SMA 网格的字段特判；实验、run、manifest 多处固定 `schema_version=1`。[延期需求](future_requirements.md) 已把正式 Schema 列为 next priority。静态检查发现 8 个 runner 分别定义 `cross_check`，9 个定义 `normalize_frame`；这说明责任分散，不表示这些函数内容完全相同。

**为什么难。** 现有策略的参数、组合构造、状态表和指标不完全同构。`symbols × cost` 的区块模型不天然等于多资产组合和多窗口实验；一个通用字典会把差异留给运行时猜测。

**建议。** 先定义少量版本化契约：数据规格、策略规格、执行规格、研究规格、解析后配置、case、统一结果、验证报告与 artifact manifest。策略特有参数由各策略自己的 Schema 管理。显式区分用户输入和填完默认值的 resolved config，并对后者计算运行身份。结果同时表达组合状态与逐证券持仓；无交易、空区间、未定义指标用明确状态表示。

**验收。** 坏类型、越界值、未知版本和缺少核对证据在计算前失败；旧 v1 配置能只读加载或显式转换，新字段有升级/兼容测试。每个指标有单位、分母、年化方式、缺失值和成本口径。不能让空的核对结果集合被解释为“全部通过”。

### GH-05：保护成交语义与两套账本的独立性

**证据。** [黄金测试](../tests/core/test_pybroker_golden.py) 覆盖 Close 信号/下一 Open、显式成交价及资金；[盘中 SMA 测试](../tests/strategies/der/test_intraday_sma.py) 有跳空和阈值优先级；[轮动测试](../tests/strategies/rot/test_nasdaq100_momentum_rotation.py) 有成员滞后和月末边界。[参考账本](../quantkit/reference.py) 目前也调用共享的 `ExplicitFillPolicy.expected_fill`。这些是现有资产与共享边界，不应把“独立”理解为完全没有共享代码。

**为什么难。** 最容易出现的是代码更整齐，但下单时点、资金可用顺序、首个持仓日或费用舍入发生变化。仅比较最终 CAGR 会漏掉相互抵消的错误。日线 OHLC 也不能自动证明盘中价格路径；重构应保留并标明现有假设。

**建议。** 先建立代表性语义基线，再移动代码。两套账本可共享公开规格和输入格式，账户状态更新、现金/持仓递推与交易汇总仍应分别实现。对已经共享的成本公式另加手算预期案例，防止两边一致地算错。统一 schema 可以复用，不能把两个账本重构为同一个函数的两个调用。

**验收。** 比较信号、订单日期/方向/数量、成交价、每日现金/持仓/净值、交易明细和指标。日期、证券、事件次序要求精确一致，浮点量使用预先登记的逐字段容差；当前正式验证器的 `1e-6` 仅作为既有规则记录，不为了让迁移通过而随意放宽。故意注入错一日成交、漏费用、错成员滞后等缺陷时，至少对应检查必须失败。

必须覆盖的最小语义集合：预热与首信号、同根 bar 可见性、下一交易日、跳空/多阈值冲突、成本与零碎股、空交易、期末未平仓、多资产共享现金、调仓顺序、基准共同起点与候选数据研究限制。

### GH-06：路径可配置之外，还需要可靠的 Run 存储

**证据。** [paths.py](../quantkit/paths.py) 从源码位置确定根目录；[load_experiment](../quantkit/experiment.py) 要求配置位于 `<workspace>/backtest/experiments`；事件写入固定 `research_events.jsonl`。同文件的 `write_json` 直接写目标文件，`record_block_complete` 读改写整个 run 记录；这些调用路径未见跨进程锁或事务。数据构建器的部分写入已经是原子替换，不能因此泛称“全项目没有原子写”。

**为什么难。** 工作树隔离和人工串行发布降低了本机冲突，但公共 CLI 的两个进程仍可能更新同一个 run。哈希说明内容是否相同，不等于代码、依赖和数据永久可取；源码移动后也不能直接拿新工作区去校验旧来源路径。

**建议。** 显式传入 workspace/data/artifact roots，将本地文件系统实现收在 `RunStore` 一类边界下。第一版可继续使用 JSON，不必先上数据库；需定义原子写、每 run 锁或严格单写者、幂等事件、区块完成提交点与崩溃恢复。分离内容身份、可变指针和审计事件。

历史迁移采用“旧运行只读 + 迁移映射 + 新运行对照证据”。不修改旧 validated 文件，不把新路径或新哈希回填为当时的事实。代码版本与可取得的源码包、环境锁和数据授权获取方式共同构成复现说明。

**验收。** 任意合法用户目录可运行；重复恢复不会多建 run；两个进程竞争同一任务得到明确串行/拒绝结果；写入中断不留下被当成完成的半文件。重构前后旧 validated 产物字节哈希不变，旧 ID 可追溯至新兼容入口。

### GH-07：将研究正确性与个人工作区习惯分层验证

**证据。** [validate_run.py](../scripts/validate_run.py) 同时检查来源哈希、账本差异、报告、完整测试、当天日志标题与目录审计，还按 experiment ID 寻找专用浏览器脚本。[audit_workspace.py](../scripts/audit_workspace.py) 根 Markdown 白名单只有 `AGENTS.md`、`catalog.md`、`log.md`。本次审计因会话索引和 macOS 元数据失败；这些失败不能推出回测数学错误。

**为什么难。** 新用户添加 GitHub 必需的根 README 就会触发本地目录规则；没有个人日志也会妨碍正式验证。反过来简单添加 `--skip-validation`，又可能把必要的账本或数据证据一起跳过。

**建议。** 输出分项、版本化验证结果，至少区分：输入资格、计算正确性、产物完整性、复现证据、报告呈现、研究晋级、可选工作区组织规则。既有本地严格流程保留为命名 profile；公共 profile 同样要求其声明范围内的完整证据。研究阶段与 run 是否完成验证是两个维度。

**验收。** 根 README、用户自定义目录及没有当天个人日志不会让数值核对失败；缺数据/缺账本核对/缺哈希仍按适用规则阻断。`skipped`、`not_applicable`、`failed`、`passed` 可区分，缺必要证据不能自动变为 `passed`。候选数据可以在明确授权的探索 profile 中产生技术验证记录，但不能获得批准数据或策略晋级标签。

### GH-08：公共测试必须在没有私人文件时仍能证明关键性质

**证据。** [CanonicalDataIntegrationTest](../tests/data/test_canonical_data.py) 的 `setUpClass` 执行标准数据构建器，之后读取真实登记与购买 ZIP，断言 QQQ/SPY 等固定行数。另一方面，GH-05 所列测试已经使用合成 bars。现状是两类测试混合，不是“完全没有可移植测试”。

**为什么难。** 新用户无法得到购买包，CI 也不应把它们作为默认依赖。简单 skip 所有数据测试会失去坏行情、交易日历和成员时点检查；无差别跑完整测试则可能重建共享派生数据。

**建议。** 将合成/可公开 fixture 的单元、黄金、契约和端到端测试设为公共默认。购买数据集成测试显式 opt-in，复制最小必要输入到独立测试输出目录或注入临时 store，禁止默认写批准库。把期望值来自手算、另一实现还是旧引擎快照写清楚。

公共 CI 先选定实际支持的 Python/OS 小矩阵，验证安装包、示例执行、账本核对和报告；私人集成检查另行运行。默认测试无需 API key、供应商额度或互联网行情请求。性能检查用固定规模与硬件说明，先建立基线，不把本机秒数变成普遍性能承诺。

**验收。** 在干净环境移除购买数据挂载后，公共测试和示例仍通过；有意破坏费用/时序/身份的用例失败。私人测试缺输入时清楚说明未运行，公共结果不借此宣称完整真实数据复现。

### GH-09：从源码工作目录运行，转为可安装的发行物

**证据。** [README](../README.md) 要求从特定本机路径使用 `backtest/.venv`；[验证入口](../scripts/validate_run.py) 也拼出该解释器路径。[reporting.py](../quantkit/reporting.py) 从源码相邻目录读模板。[浏览器检查](../scripts/smoke_report_ui.mjs) 默认 Chrome 位于 macOS 应用路径，但已有 `QUANT_CHROME_PATH` 覆盖能力。[manage_worktree.py](../scripts/manage_worktree.py) 假设特定 Git 布局与共享文件集合。

**为什么难。** pip 安装后目录结构、调用位置和 Git 元数据都可能不同；模板漏进 wheel、从包目录写数据、缺 Node/浏览器，都可能造成“作者电脑可用”。worktree 的符号链接实现了共享，不会自动把目标变成操作系统层面的只读文件。

**建议。** 增加明确包元数据、入口命令和打包资源；运行数据写入用户选择的 workspace，使用当前解释器或显式配置。拆分核心、引擎、绘图/UI、数据 provider 与开发依赖，库依赖范围和可复现实验锁文件各司其职。明确 Node、浏览器与可选 PDF 工具的使用边界。第一版可以只承诺经过验证的 Linux/macOS，不必为“完整平台”立即支持所有操作系统。

Git 工作树和 Agent Skill 留作可选开发工作流；正常用户不应先创建工作树才能研究。私人集成测试的只读约束需要程序边界或隔离输入保证，不能仅依赖符号链接和约定。

**验收。** 从构建的 wheel 安装后，在仓库外、带空格的路径运行示例并生成报告；模板和 JS 资源齐全；未安装可选依赖时给出准确提示。普通安装不要求个人 Skill、Keychain、Git 仓库或 `.venv` 恰好位于指定位置。

### GH-10：报告较容易提取，应用仍须统一数据与结果入口

**证据。** [报告渲染器](../quantkit/reporting.py) 无其他 `quantkit` 模块导入，隔离程度较好，但模板路径和 `zh-CN` 固定。多数文本已有 HTML 转义，`summary_html` 则作为可信片段直接插入。[指标实验台](../../research/indicator_lab/app.py) 已有 CSV 上传，默认仍先选本机批准数据；[双均线数据源](../dual_sma_lab/data_sources.py) 读取本地 registry 与历史证券资料。

**为什么难。** 外部用户没有本机目录，报告也不能默认理解 QQQ 等固定图 ID。由用户输入或模型生成的文字如果进入可信 HTML 接口，需要明确处理边界。把浏览器中的对齐/定投试算误记为正式回测，则会破坏结果身份。

**建议。** 两个实验台共享数据发现与导入契约，默认提供明确标识的合成样例，也支持外部文件；保留“View 不产生正式策略收益”“交互探索不自动登记为 validated”的区分。报告读取标准结果和冻结规格，资源随包安装，语言与文案可配置。普通文本走转义路径，可信 HTML 扩展单独声明；本次没有据此认定存在已验证漏洞。

**验收。** 安装报告/UI 依赖后，无本机 registry 可启动两个应用；上传坏数据得到明确错误；改变参数可以观察/执行，但不会悄悄覆盖旧 run。生成的 HTML 离线打开可用，策略说明在指标前，图表交互、导出与打印均在声明支持的浏览器检查。正式指标不会随浏览器显示操作被改写。

### GH-11：把研究谱系从个人分类推广为可复用模型

**证据。** [架构](architecture.md) 和 [lineage.json](../experiments/lineage.json) 已把研究假设、版本、父子关系和 View 区分开；[生成器](../scripts/build_research_catalog.py) 自动生成多种入口。本地组织规则依赖 DER/ROT/TIM 目录、命名和日期；旧需求和交接说明也有与当前实现不同的数量、状态。

**为什么难。** 外部研究者会有不同 program、分类和版本策略。把现有 83 个研究节点当成平台必须自带的配置，会同时带入私人假设、授权未清的数据和无法下载的 run。只删掉历史又会丢掉研究工具与个人记录的边界说明。

**建议。** 将 program、展示名、父子理由、研究阶段等作为 workspace 数据，DER/ROT/TIM 成为本机配置及公开示例之一。稳定 ID 与目录展示名分离。用一个包含正/负结果及分叉的小型合成研究图证明目录生成；本机历史保留兼容读取。面向公开仓库的 README 说明问题、安装、最小实验、数据假设、扩展方法与限制，英文快速开始可优先于整套历史翻译。

**验收。** 在新 workspace 新建自定义 program 不改核心；索引可由机器数据重建，父子边理由只写一次；无交易、未验证和被拒绝的实验也能清晰展示。旧历史不能因渲染或目录迁移获得更高研究阶段。

### GH-12：公开文件集要显式选择，不能直接推当前仓库

**证据。** 当前仓库包含大量研究配置、来源清单、历史说明和被跟踪的派生成员 CSV；许多大型 run 产物又被忽略。本次只检查当前树和少量相关元数据，**没有完成全 Git 历史、密钥、全部第三方来源或数据授权审计**。

**为什么难。** 删除工作区文件不会自动删除 Git 历史中的版本；忽略的报告可能仍是公开文档链接的目标。HTML 可能嵌入完整价格序列，JSON/manifest 也可能包含本机路径或私人研究信息。“代码可公开”不能代替发行包审查。

**建议。** 先维护显式导出清单，在独立 GitHub-ready 目录预览完整发行物，检查源码、样例、文档、wheel/sdist、HTML 和历史范围。私人工作区继续保留原证据。发布时可选择经过审查的新公共仓库，或经过审查的历史迁移；今天不重写已有历史，也不连接远端。若发现真实凭据，记录文件位置并单独处理，不把值复制到文档。

**验收。** 每个公开文件都有纳入理由，数据或嵌入序列有授权依据；没有真实密钥、个人会话索引、私人路径和不可达的必要链接；依赖声明、安装包与 README 对实际功能一致。所有公开历史引用有证据可取得，无法公开的数据明确要求用户自行合法提供。

## 5. 建议的边界与目标结构

以下是**设计提案**，路径和接口尚未创建。先稳定职责，再决定最终文件名；不要求一次搬迁到该目录。

```text
公共仓库
├── pyproject.toml / README.md / LICENSE / THIRD_PARTY_NOTICES
├── src/quantkit/
│   ├── domain/             数据、配置、结果、验证记录的纯类型与 Schema
│   ├── indicators/         纯指标，无引擎和 UI 导入
│   ├── strategies/         信号或订单计划、策略特有配置
│   ├── engines/            PyBroker 等执行适配器
│   ├── reference/          独立账户递推及手算基线
│   ├── metrics/            明确单位和时间口径的结果统计
│   ├── datasets/           CSV/合成/provider 接入、质量与用途规则
│   ├── experiments/        RunStore、恢复、证据、研究阶段及谱系
│   ├── reporting/          报告模型与随包模板资源
│   └── cli/                薄编排，不容纳策略算法
├── apps/                   指标与双均线实验台
├── examples/               可公开的小型完整研究流程
├── tests/                  公共默认测试与显式 opt-in 集成测试
├── docs/                   入门、数据/执行语义、扩展、迁移、限制
└── .github/workflows/      包构建、公共测试、示例与报告检查

用户自己的 workspace（与安装目录分开）
├── workspace 配置         program、数据根、产物根、验证 profile
├── datasets/              用户自行提供的数据及授权/来源元信息
└── experiments/           私人的研究定义、run、事件、谱系与产物
```

依赖方向：应用/CLI 调用公共服务；服务编排数据、策略、引擎、参考核对、结果存储和报告；这些模块依赖纯契约。PyBroker 类型止于 adapter，购买包路径止于相应 data adapter，DER/ROT/TIM 止于 workspace 配置。只有需要的功能才加载 UI、浏览器或供应商依赖。

建议先定下面的最小接口语义，暂不设计庞大的插件框架：

| 边界 | 输入 / 输出 | 必须保持的约束 |
| --- | --- | --- |
| Dataset adapter | 数据规格 → 标准行情、身份/成员信息、来源与质量记录 | 加载不等于批准；获知时间与有效时间独立 |
| Strategy | 截止当前可见的信息、冻结参数 → 信号/订单计划/目标仓位 | 不读取未来；不同策略可有不同计划类型 |
| Engine adapter | 标准数据、计划、执行/资金规则 → 标准账户与交易结果 | 不隐含默认成交价、成本、日历或调仓顺序 |
| Reference evaluator | 同一规格和输入 → 独立计算的对照结果 | 不复用主引擎的账户状态递推 |
| Metrics | 账户路径、交易、统计规格 → 指标及定义 | 单位、现金流、持仓/日历年化、基准起点清楚 |
| RunStore | frozen config、区块结果、证据 → 不可覆盖的 run | 原子提交、恢复、完整性、旧版本读取 |
| Validator | run + profile → 分项证据与结论 | 缺必要证据失败；技术通过不等于研究晋级 |
| Report | frozen config + 标准结果 + 验证摘要 → HTML/其他呈现 | 展示不重新定义正式结果 |

指标契约尤其要保留当前 [metrics.py](../quantkit/metrics.py) 对日历 CAGR 与持仓时间年化的区分。报告中的相似名称不能掩盖不同分母。

## 6. 分阶段重构顺序

每阶段都提交可单独审查的变更，避免同时改策略、数据与账本。支持旧入口的兼容层在对照完成前保留。下表是建议顺序，许可/来源盘点可以与接口设计并行推进。

| 阶段 | 交付内容 | 退出条件 | 暂时保留 |
| --- | --- | --- | --- |
| M0：冻结基线与公开边界 | 模块/策略范式清单、依赖许可清单、公开文件选择规则、代表案例预期行为 | 每项能力有现有入口、数据依赖、证据与迁移状态；无不明来源材料被默认纳入 | 全部旧实现与历史 run |
| M1：契约与纯核心 | 版本化模型/Schema、输入与 resolved config、纯指标/执行规格、旧 workspace adapter | 坏输入早失败；纯模块无引擎/UI依赖；旧路径对照通过 | 旧 runner、目录和本机 registry |
| M2：贯通代表案例 | 安装包、合成/CSV adapter、稳定最小 CLI、三种语义的完整实验与报告 | 在仓库外从安装包完成三条通路；公共测试不访问私人目录 | 未迁移范式明确登记，整体迁移仍未完成 |
| M3：生命周期与验证 | RunStore、并发/崩溃恢复、证据 profile、公共 CI 与私有测试隔离 | 完整 run 不依赖当天日志或个人分类；缺证据失败；旧 run 不改写 | 本机严格工作流作为独立 profile |
| M4：覆盖整个平台 | 逐类迁移其余策略/参数研究、provider/候选数据工具、两个实验台、谱系和文档 | 每个现有独立范式有支持状态和证据；公开功能均走公共入口；私人数据可通过私有配置接入 | 需权利审查的原始/派生数据及私人研究档案 |
| M5：公共发行验收 | 审查后的导出目录、许可/归属材料、干净安装、完整示例、文档与版本记录 | 第 9 节检查表逐项有证据，公开引用可达，声明与支持矩阵一致 | 未实现的实盘、调度等按能力边界继续延期 |

### 三个最先迁移的案例

| 案例 | 为什么必须有 | 可复用的现有依据 | 迁移检查重点 |
| --- | --- | --- | --- |
| 单标的 Close 信号、下一 Open 成交 | 最小闭环：输入、预热、信号、费用、账本、报告 | SMA/StochRSI 与 `test_pybroker_golden.py` | 首信号、错一日成交、零碎股、现金和基准起点 |
| 日线 OHLC 下的盘中阈值策略 | 防止接口只适合简单收盘择时 | DER `intraday_sma` / TIM 动态阈值相关实现 | 盘前可计算信息、跳空、多阈值优先级和路径假设 |
| 历史时点多资产轮动 | 防止接口只能容纳单证券 | Nasdaq 动量轮动与组合双账本测试 | security_id、获知延迟、月末/次日、退出成员、共享现金、调仓顺序 |

三个案例均先用小型合成数据，以手算/独立递推确立预期，再在有权使用的本机数据上做旧/新实现比较。合成行情应明显标识，不用于宣传真实收益。

随后按“独立行为范式”迁移其余能力，而不是按 83 个 experiment 逐个复制脚本。同算法仅参数不同可统一配置；持仓递推、成交或研究选择规则不同则保留独立实现与测试。建立清单字段：现有模块、调用入口、范式、旧证据、目标接口、状态、等价检查、公开数据条件。

建议状态为：`unreviewed → inventoried → adapted → equivalence_checked → documented`。无法公共复现的真实数据案例额外标识 `private_data_required`，不能用这个标签掩盖代码本身尚不可安装。未经逐项确认，不把未迁移能力从最终范围中删除。

### 每个迁移 PR 的最小证据

1. 只陈述本次移动的职责及保持不变的策略语义，列出旧入口到新入口的映射。
2. 保存至少一个正常案例和一个能触发边界错误的案例；共享公式有独立预期值。
3. 旧/新实现比较明细账户路径与事件，不仅比较聚合收益。
4. 若发生预期差异，先登记为行为变更并新建研究/验证证据；不能以“重构”名义改旧 run。
5. 运行受影响的公共测试、必要私有集成检查和安装/资源检查，记录未运行部分及原因。
6. 更新支持矩阵、兼容入口和迁移状态，保留明确恢复点。

## 7. 公开与私有材料的处理表

这是拟议的导出规则，不是现有材料已经获准公开的结论。

| 材料 | 建议处理 | 发布前需确认 |
| --- | --- | --- |
| 自有平台代码、测试、模板 | 审查后纳入 | 贡献来源、复制代码归属、第三方声明 |
| 自行构造的 OHLCV/成员 fixture 与示例 | 作为默认演示输入 | 来源说明、生成方法、数据许可、无私人原文 |
| 供应商 adapter 与 registry 格式 | 公开代码/Schema 和示例配置 | provider 条款、凭据不进入文件、用户自行供给数据 |
| 两组购买原始包、解压副本 | 留在私有数据区 | 任何未来再分发必须另有明确依据 |
| 标准价格、成员 CSV、供应商原始响应 | 不默认纳入 | 派生数据权利、服务条款、范围与归属；免费获取不等于可再分发 |
| 真实研究配置与策略参数 | 逐项选择 | 作者是否希望公开、是否嵌入私人信息、依赖数据能否取得 |
| HTML/PDF/图表/JSON/NPZ | 与数据一并审查 | 内嵌价格、完整序列、来源路径和可逆导出；不能只看扩展名 |
| 历史 validated run | 私有原件保持原样；公开副本需单独说明 | 数据公开权、源码/环境可取、脱敏后是否仍保留原验证意义 |
| raw manifest、日志、会话索引、机器路径 | 公共版按用途重新整理或排除 | 不复制本机清单、凭据或完整对话；必要 provenance 使用稳定逻辑标识 |
| Git 历史 | 先选择发布方式，再检查选定范围 | 当前文件删除并不能证明旧对象中不存在敏感材料 |
| README 与研究演示 | 公共版本重新组织 | 清楚区分平台原创能力、外部引擎、样本内研究和未实现功能 |

如果为公开展示而删去报告的内嵌数据，应把结果作为新的展示导出物，保留其来源说明。不能把删改过的文件继续当作原始 validated 产物。

## 8. 测试与验证矩阵

| 层次 | 默认输入 | 应证明什么 | 执行边界 |
| --- | --- | --- | --- |
| 契约/指标单元测试 | 小型自建数组与表 | 类型、窗口、预热、单位、缺失值、指标定义 | 公共默认，无供应商请求 |
| 成交与账本黄金测试 | 手算 bars/订单与成员事件 | 时序、成本、现金守恒、事件顺序、双账本差异 | 公共默认，包含故意错误反例 |
| 数据质量与 PIT 测试 | 合成异常价格/身份/成员记录 | 坏 OHLC、重复/缺失、成员延迟、代码变化、退市 | 公共默认，不依赖真实购买包 |
| 安装与端到端 | wheel、合成 workspace、三条代表通路 | 任意 CWD、资源完整、run→验证→报告→谱系 | 公共 CI，明确 Python/OS/浏览器矩阵 |
| 恢复与竞争测试 | 临时 store、人工中断与两个进程 | 不覆盖、不丢完成状态、正确恢复或拒绝 | 公共 CI，测试输出隔离 |
| UI/报告 | 固定小结果，离线 HTML | 图表、筛选、导出、策略说明与正式结果边界 | 声明支持的浏览器，不要求私人图 ID |
| 私人数据集成 | 合法取得的固定购买数据/来源存档 | 与本机研究和旧实现等价、真实 schema 兼容 | 显式启用，独立输出，无公开凭据 |
| 性能基线 | 固定规模和配置 | 时间、峰值内存、缓存冷/热与规模退化 | 先量测；不以小样例替代大网格结果 |

公共默认测试不需要全量真实历史数据，但必须覆盖相同的关键错误类别。私有测试也不能因为跑在本机，就自动获得写批准价格库的权限。

当前大型网格、分块计算和缓存的行为应在对应范式迁移时测量。没有 profiling 证据前，不先切换存储格式、并行框架或计算引擎。
