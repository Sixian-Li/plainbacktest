# 回测研究晋级规则

## 目的

把“看起来不错”拆成可追溯的研究阶段，防止在同一段历史上反复选参数、再把结果误认为样本外证据。每个实验必须在 `experiment.json.research` 中预先写明假设、主指标、选择规则、验证计划、晋级标准和否决条件。

## 阶段

1. `idea`：只有待检验想法，尚未形成可执行定义。
2. `exploratory`：允许在开发数据上比较参数和观察平台，但结果只用于形成候选，不代表未来表现。
3. `walk_forward_validated`：窗口、重估频率和选参规则事先冻结；只按连续样本外净值判断。
4. `locked_test_validated`：候选规则锁定后只打开一次保留测试集，不因结果重新选参。
5. `paper_trading`：用真实时间顺序生成模拟决策，检查数据延迟、信号与执行链路。
6. `small_capital_candidate`：工程与研究门禁均通过，才可讨论小资金上线；不等同于自动获得实盘授权。
7. `rejected` / `archived`：否决或停止研究，并保留原因和历史运行。

阶段不能由一次高收益自动提升。晋级前必须满足当前实验预先记录的 `promotion_criteria`；触发 `rejection_conditions` 时应否决、扩大研究范围或建立语义不同的新实验，而不是在原实验中改规则掩盖结果。

## 实验与运行

- 实验（Experiment）是长期研究问题和固定语义，例如“QQQ/SPY 的 SMA200 双阈值是否存在稳定参数平台”。
- 运行（Run）是该实验的一次具体执行，冻结当时的数据、配置、代码版本、成本、环境和全部输出。
- 同一实验可因数据更新、代码修正或复现检查而有多次运行；改变入场语义、成交时点或研究问题时应新建实验。
- 参数网格中的单个参数组合称为 case，不称为 run。
- 每次研究完成后在 `lineage.json` 登记流派、版本、父子关系及修改理由，并运行 `scripts.build_research_catalog`；总演化史与 DER/ROT/TIM 独立演化史均由证据自动重建，不手工同步。

只有通过强制验证门禁的 run 才可成为实验的 `latest_validated_run_id`，且验证后的目录禁止改写。
