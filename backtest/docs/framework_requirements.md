# Quant 框架需求与筛选清单

> 文档用途：这是用户与后续协作 agent 选择、搭建和评审 Quant 框架时的共同依据。本文只描述框架能力，不记录具体策略想法；策略研究思路见 `ideas.md`。

## 1. 当前目标

在本地搭建一个以回测为核心、以后可以扩展到 IBKR 模拟盘和实盘的 Quant 框架。近期流程为：

```text
导入数据
→ 清理与校验
→ 输入策略
→ 回测
→ 参数稳健性与样本外验证
→ 生成结果和图表
→ 未来接入 IBKR 模拟盘
→ 小资金实盘与自动化
```

当前主要研究美股日线，重点标的是 QQQ、SPY 和少量个股；SPY 暂时代替数据未通过门禁的 VOO。没有日内交易，通常单日最多买卖一次，但需要比较开盘和收盘执行。

## 2. 总体架构

框架采用模块化设计，不要求一个 GitHub 项目包办全部功能：

```text
数据层
  ↓
统一策略与信号层
  ├── 回测执行器
  └── 未来的 IBKR 执行器
  ↓
标准化结果
  ├── 指标与交易账本
  ├── 交互式可视化
  └── Markdown / HTML / PDF 报告
```

核心原则：

- 数据、策略、回测、可视化和券商连接相互解耦。
- 回测与 IBKR 共用同一套策略和信号定义，只替换执行器。
- 策略计算代码只写一次；标的、时间、参数和执行方式均通过配置传入。
- 单次研究保存为独立 experiment/run，不使用 Git branch 保存参数或回测结果。
- Git branch 只用于正常的软件开发。

## 3. 数据层要求

- 第一版读取本地 CSV，未来可以替换或增加数据源。
- 原始数据永久保留且不覆盖，清理后的标准数据单独存储。
- 支持美股日线常规交易时段 OHLCV。
- 支持股票代码表和美股交易日历。
- 识别并报告重复日期、缺失值、缺失交易日、零价格、异常价格和异常成交量。
- 明确日期、时区、币种和交易时段。
- 区分原始价格、复权价格、现金分红和拆股。
- 用适合的复权序列计算长期指标，用原始 OHLC 模拟真实成交。
- 数据版本或数据指纹必须随实验保存，确保结果可复现。
- ETF 成立前可以使用对应指数或其他产品作为代理，但必须明确分段和标注，不能伪装成真实 ETF 历史。

数据实现倾向：根据下载数据的真实 CSV 格式编写薄适配层；不为数据清理单独引入庞大框架。

## 4. 回测引擎要求

- 支持日线级回测。
- 支持单标的和多标的同步回测。
- 多标的可以共享现金、统一分配资金和进行组合级约束。
- 第一版以只做多为主。
- 账户模型为未来融资预留接口，包括融资额度、利率和保证金约束；第一版不要求复杂做空借券。
- 支持开盘、收盘等不同成交时点。
- 明确信号产生时间和订单执行时间，禁止未来数据泄漏。
- 当日收盘后才能确认的信号，默认最早在下一交易日开盘执行。
- 如果测试当日收盘执行，必须能够明确表达所依赖的信息假设。
- 支持手续费、滑点、最小交易单位和可选的成交限制。
- 支持现金、持仓、订单、成交、分红、拆股和融资成本的账户账本。
- 所有收益必须能够由逐笔成交和账户流水复算。

## 5. 策略与实验配置

- 策略代码与实验参数分离。
- 同一策略可以仅通过更换标的、日期和参数重复运行。
- 支持单标的策略模板、多标的轮换模板和组合持仓模板。
- 标的列表、参数、候选参数范围、开收盘执行、回测日期、交易成本和基准均为配置。
- 同一策略可以批量运行少量标的。
- 允许每个标的使用独立参数，也能使用全标的共用参数作为对照。
- 未来 skill 可以把自然语言策略转换为标准实验配置并调用框架，但 skill 不承担底层收益计算。

## 6. 参数研究与验证

- 支持少量参数和局部参数扫描，典型规模为几十至几千次回测。
- 保存全部参数结果，而不只保存历史收益最高的参数。
- 能输出一维参数曲线和二维参数热力图所需的标准数据。
- 支持判断最优值附近是平滑稳健区域还是孤立异常尖峰。
- 支持固定参数研究。
- 支持严格按时间顺序的 walk-forward 动态选参。
- 支持扩展窗口、滚动窗口和时间衰减等历史记忆方式。
- 普通随机 K-fold 不作为时间序列策略的默认验证方法。
- 调整参数后不能继续把同一验证期当作未见数据；应保留最终锁定测试期或使用连续样本外结果。
- 固定版和动态版必须基于连续样本外资金曲线公平比较。

## 7. 结果、报告与复现

每次 experiment/run 至少保存：

- 标的与基准
- 数据范围、数据版本和预热区间
- 策略版本和完整参数
- 信号时间与执行规则
- 初始资金、费用、滑点和融资假设
- 订单、成交、持仓和现金流水
- 每日账户净值和收益率
- 累计收益、年化收益和年化波动率
- Sharpe、Sortino、最大回撤和回撤持续时间
- 交易次数、胜率、换手率和持有时间等交易统计
- 与买入持有、QQQ 或 SPY 基准的统一口径比较
- 运行时间、代码版本和异常警告

PDF 或 HTML 不是唯一结果来源；同时保存机器可读的配置、指标、每日净值和交易记录。

## 8. 可视化要求

可视化可以由独立库完成，不要求回测框架自带完整 GUI。

- 优先支持浏览器可打开的交互式 HTML。
- K 线图支持拖动、缩放、滚动、时间范围选择和悬停查看。
- 可以叠加均线、RSI、买卖点和参数调整时点。
- 可以在同一图中比较策略净值、QQQ、SPY 和买入持有。
- 支持回撤曲线，以及不同参数、固定/动态、开盘/收盘版本对比。
- 净值图支持明确勾选显示系列，并可把当前可见区间首日的各曲线对齐到同一基准净值。
- 支持在当前可见区间内，以基准首日净值为总预算、按指定次数等额分批投入的定投情景；未投入现金、费用和口径必须写明。
- 图表只读取标准回测结果，不在可视化层重新计算策略收益。
- 报告首页必须像研究员向人解释策略一样，按“交易对象、买入、卖出、信号确认、成交、仓位与成本”的阅读顺序写完整句子；不得用机器字段表代替说明。
- PDF 首页不得展开 JSON、Python 字典、配置代码或完整参数树；完整参数保留在机器快照和网页折叠附录中。
- 已验收的页面交互应抽成版本化项目模板供后续实验复用；skill 记录选用与验收流程，不保存某次实验的成品 HTML。
- Markdown 用于研究结论，PDF 用于固定版式存档。
- 第一版可以只生成独立 HTML；以后如需用户自行选参数并运行，再增加 localhost 操作界面。

## 9. IBKR 与自动化的未来要求

近期不要求实盘连接，但核心设计不能阻碍未来扩展：

- 通过独立 broker adapter 接入 IBKR。
- 先接模拟盘，再进入小资金实盘。
- 回测执行器和 IBKR 执行器消费同一策略信号或订单意图。
- 支持订单预览和人工确认模式。
- 支持金额、仓位、融资和单日交易限制。
- 支持重复订单保护、数据缺失保护和紧急停止。
- 支持断线恢复、失败重试、日志和通知。
- 支持 IBKR 持仓、现金、订单与本地账本核对。

## 10. GitHub 候选项目评估维度

选择核心框架时需要检查：

- 最近维护状态、发布记录、issue 和 pull request 活跃度。
- Python 和 macOS 兼容性。
- 开源许可证及个人研究、修改和未来使用限制。
- 文档质量、示例质量和自动化测试情况。
- 是否容易读取 Pandas/Polars/CSV 数据。
- 是否能导出完整、透明、可复算的结果。
- 日线与少量标的下的正确性和易扩展性，优先级高于极端性能。
- 是否能在不修改框架内部代码的情况下实现自定义策略、账户规则和数据适配器。
- 是否与 Plotly 等可视化库解耦。
- 是否允许未来增加独立 IBKR adapter。
- 依赖复杂度、安装难度和版本升级风险。
- 是否存在隐藏的云服务、账号、付费数据源或平台绑定。

不因为框架附带数据下载器、漂亮图表或实盘接口，就忽略其核心回测正确性和可维护性。

## 11. 框架筛选 Checklist

### 11.1 必须满足

`[x]` 表示已经由本地实现或自动测试验证，不只是根据文档推断；未勾选项仍是后续门槛。

- [x] 当前仍有可信维护，或代码足够小且稳定到可以由我们接管维护
- [x] 许可证允许本地个人研究和修改
- [x] 可在本地 Python/macOS 环境运行
- [x] 可读取自定义本地 CSV，不绑定指定数据商
- [x] 支持日线 OHLCV 和交易日历
- [x] 能严格表达信号时间与开盘/收盘成交时间
- [x] 能防止或容易测试未来数据泄漏
- [x] 支持单标的回测
- [x] 支持多标的同步回测和共享现金账户
- [x] 支持只做多、现金和组合仓位约束
- [x] 支持手续费和滑点
- [ ] 能正确处理或允许我们接管分红、拆股和复权逻辑
- [x] 策略代码与标的、日期和参数配置分离
- [x] 同一策略无需复制代码即可更换标的和日期
- [x] 支持局部参数扫描
- [ ] 可以实现严格的 walk-forward 验证
- [x] 输出逐笔订单、成交、持仓、现金和每日净值
- [x] 回测收益能够从账本复算
- [x] 结果可以导出为标准表格或文件供 Plotly 和报告层使用
- [ ] 可以为未来 IBKR adapter 提供稳定的策略信号或订单接口
- [x] 核心行为能够编写自动化测试
- [x] 每次实验可以保存完整配置和代码/数据版本

### 11.2 最好满足

- [x] 几十至几千组日线参数回测具有可接受的速度
- [ ] 原生或容易实现多标的轮换和目标权重再平衡
- [x] 容易实现每个标的独立参数
- [ ] 容易实现扩展窗口、滚动窗口和时间衰减选参
- [ ] 支持融资成本和基础保证金约束
- [x] 社区、文档和示例足以帮助排查边界问题
- [x] 依赖规模适中，升级路径清晰
- [x] 可与交互式 HTML、Markdown 和 PDF 报告流水线协作

### 11.3 当前不强制要求

- [ ] 框架自带行情下载器
- [ ] 框架自带完整网页 GUI
- [ ] 框架自带 Plotly K 线图
- [ ] 框架原生连接 IBKR
- [ ] Tick、订单簿或高频撮合
- [ ] 复杂做空借券模型
- [ ] 云端部署或多人在线服务
